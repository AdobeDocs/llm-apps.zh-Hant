# 疑難排解 {#troubleshooting}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]目前在Beta中。
>
>此處顯示的功能、工作流程和UI不一定代表產品的最終狀態。 若要加入Beta，請傳送電子郵件至llm-apps-beta@adobe.com。

從可觀察的症狀開始。 進行疑難排解時，請勿共用認證、權杖、私人MCP URL或敏感處理常式結果。

## 應用程式建立和動作產生

| 症狀 | 嘗試什麼 |
|---------|-------------|
| Adobe受管理基礎架構設定失敗 | 在&#x200B;**安裝失敗**&#x200B;下讀取錯誤，然後選取&#x200B;**重試**。 如果頁面無法檢查進度，請選取&#x200B;**再次檢查**；在背景中繼續安裝 |
| 沒有可用的AEM程式 | 請要求您的管理員提供程式存取權。 如果載入失敗，請選取&#x200B;**重試載入程式** |
| 新存放庫未出現 | 使用&#x200B;**連線其他存放庫**&#x200B;來授予Adobe LLM應用程式GitHub應用程式存取權，返回精靈，然後選取&#x200B;**重新整理組織和存放庫** |
| 動作或Widget存放庫驗證失敗 | 使用相容的現有專案或空的存放庫。 使用個別的存放庫執行動作和Widget，然後再次選取&#x200B;**驗證存放庫** |
| 未偵測到AEM程式碼同步 | 為Widget存放庫安裝AEM程式碼同步，在確認頁面上新增您為網站管理員，返回精靈，然後選取[驗證AEM程式碼同步安裝]&#x200B;**&#x200B;** |
| 建立應用程式時沒有產生動作 | 應用程式建立只會設定基礎結構。 在應用程式頁面上，選取&#x200B;**自動建置動作**，輸入&#x200B;**您的網站**，然後選取&#x200B;**建置我的動作**。 請參閱[建立動作](/help/guides/creating-actions.md) |
| 動作仍在產生中 | UI預估產生最多需要30分鐘。 在「動作」頁面上追蹤進度，或離開頁面並於稍後返回 |
| 動作產生報表失敗 | 確認網站是透過HTTPS公開，且對於您自己的存放庫，存放庫存取權仍然有效。 如果問題仍然存在，請聯絡Beta團隊並提供顯示的錯誤訊息 |

## 動作和處理常式

| 症狀 | 嘗試什麼 |
|---------|-------------|
| 未叫用動作 | 在交談中啟用應用程式的外掛程式或聯結器。 確認動作設定中的&#x200B;**向AI模型公開**，且應用程式頁面上的動作&#x200B;**可見度**&#x200B;開關已開啟。 改善說明並重新部署中繼資料變更 |
| 空白或錯誤回應 | 執行`npm test`，然後使用MCP檢查程式或`curl`呼叫處理常式。 檢視[本機處理常式開發與測試](/help/reference/development.md) |
| 處理常式在本機運作，但在部署後無法運作 | 檢查最新的推播認可、確認執行階段設定，以及確認動作程式碼識別碼符合`actions/<code-identifier>/index.js` |
| 無法將產生的動作標示為已檢閱 | 確認處理常式和Widget產生成功。 檢查產生的提取要求是否發生合併衝突，重新載入動作，然後再次選取&#x200B;**標示為已檢閱** |

## Widget

| 症狀 | 嘗試什麼 |
|---------|-------------|
| Widget未呈現 | 驗證指令碼URL、Widget URL、HTTPS、EDS出版物、CSP網域和CORS標頭 |
| Widget會呈現但未顯示任何資料 | 使用MCP檢查器呼叫處理常式，並將其`structuredContent`圖形與從`bridge.toolResult`讀取的欄位進行比較 |
| Widget可在直接預覽中運作，但無法在ChatGPT中使用 | 直接預覽可能會使用範例資料。 測試已部署的處理常式結果，並驗證CORS和CSP允許EDS來源 |
| 已封鎖瀏覽器請求 | 僅將所需來源新增至正確的CSP欄位並重新部署 |
| HTTP標題編輯器無法儲存設定 | 使用[AEM組態服務](https://aem.live/docs/config-service-setup)或要求EDS系統管理員初始化站台標頭組態 |

當完整的`bridge.toolResult`值可能包含個人或敏感資料時，請勿記錄這些值。

## 部署

| 症狀 | 嘗試什麼 |
|---------|-------------|
| 在&#x200B;**準備**&#x200B;期間部署失敗 | 確認處理常式存放庫已連結，且您的Adobe Developer Console存取權仍然有效 |
| 在&#x200B;**建置應用程式**&#x200B;期間部署失敗 | 在本機執行`npm install`、`npm test`和`npm run build`。 修正相依性、語法或測試失敗，並推送變更 |
| 部署成功，但缺少變更 | 確認預期的認可已推送並重新部署到相同環境 |
| 動作仍為&#x200B;**未部署** | 在檢閱動作或變更其中繼資料後再次部署 |

## 驗證 {#authentication}

適用於&#x200B;**[!UICONTROL 啟用驗證]**&#x200B;已開啟。 請參閱[使用您自己的身分提供者來驗證一般使用者](/help/guides/authentication.md)。

| 症狀 | 嘗試什麼 |
|---------|-------------|
| 儲存設定後，動作仍為公開狀態 | 將應用程式再次部署至該環境。 驗證變更會在下次部署時生效 |
| 切換環境後設定看起來錯誤 | 確認&#x200B;**[!UICONTROL Workspace]**&#x200B;選取器顯示您打算的環境。 **[!UICONTROL 階段]**&#x200B;和&#x200B;**[!UICONTROL 生產]**&#x200B;是獨立設定的 |
| 登入未開始 | 確認您已在啟用驗證後部署應用程式，且動作使用&#x200B;**[!UICONTROL 必要]**。 **[!UICONTROL Optional]**&#x200B;動作只有在處理常式要求登入時才會提示 |
| 平台將使用者傳送至錯誤的登入頁面 | 驗證&#x200B;**[!UICONTROL 簽發者]**&#x200B;是否與您的身分提供者的簽發者URL完全相符，以及它是否可透過公用HTTPS連線 |
| 登入成功，但所有呼叫仍遭拒絕 | 確認您的身分提供者會發行權杖，其對象為該環境的應用程式MCP伺服器URL，且權杖是使用非對稱演演算法簽署的JWT。 檢視[權杖需求](/help/reference/authentication-reference.md#token-requirements) |
| 身分提供者不會接收任何流量 | 您的提供者的探索、授權和權杖端點必須可透過公開HTTPS連線。 檢查前面的防火牆、WAF或IP允許清單 — 您的應用程式在提供者無法使用時仍可連線 |
| 身分提供者拒絕為要求的對象核發權杖 | 有些提供者只會針對已向其註冊的資源發出代號。 確認應用程式的MCP伺服器URL已註冊為身分提供者中的資源識別碼 |
| 登入時未請求新新增的範圍 | LLM平台會快取應用程式發佈的中繼資料幾分鐘。 請稍候，然後重試登入 |
| 系統會要求使用者再次登入範圍 | 此動作需要權杖未攜帶的範圍。 在您的身分提供者中，將範圍新增至使用者端的授權，或從動作中移除此範圍 |
| 使用者會收到重複的登入提示 | 一種處理常式，每次呼叫時都會傳回`extra.challengeAuth()`，而不會檢查呼叫者的身分要求，在驗證後再次登入。 請求驗證僅當缺少動作所需的身分時 |
| 在使用者到達您的身分提供者之前，登入會遭到拒絕 | LLM平台傳送的重新導向URI未向授權伺服器註冊。 有些平台會針對每個聯結器發出不同的值，因此請註冊聯結器設定畫面上顯示的值 |
| 儲存被不支援的範圍訊息封鎖 | 將領域新增至&#x200B;**[!UICONTROL 支援的領域]**，或從需要它的動作中移除它 |
| 公用動作仍會提示登入[!DNL Claude] | 檢查聯結器是否在需要時使用&#x200B;**[!UICONTROL 登入]**，而非&#x200B;**[!UICONTROL 立即登入]**。 若為較舊部署的應用程式，請更新執行階段並重新部署。 目前執行階段上的混合式應用程式可匿名呼叫公用動作 |
| **[!UICONTROL 選擇性]**&#x200B;動作傳回登入文字，但沒有Claude登入提示 | `extra.challengeAuth()`是ChatGPT工具結果挑戰。 對於可攜式登入閘道，請使用&#x200B;**[!UICONTROL 必要]**&#x200B;動作，讓執行階段傳回Claude預期的HTTP挑戰 |
| 即使每個動作是&#x200B;**[!UICONTROL 無]**，應用程式仍會提示登入 | 關閉&#x200B;**[!UICONTROL 啟用驗證]**&#x200B;並部署。 當啟用時，應用程式會通告授權伺服器，即使未閘道任何動作亦然 |

請勿將存取權杖、宣告集或身分提供者使用者端密碼貼到支援要求中。

## ChatGPT增效模組

| 症狀 | 嘗試什麼 |
|---------|-------------|
| 外掛程式未出現 | 開啟[chatgpt.com/plugins](https://chatgpt.com/plugins)，確認您的帳戶或工作區允許自訂MCP伺服器，並安裝或連線產生的外掛程式 |
| 外掛程式建立失敗 | 從&#x200B;**再次複製完整的HTTPS MCP伺服器URL測試應用程式**，並選擇符合應用程式的驗證方法。 僅針對公用應用程式使用&#x200B;**無驗證**，而非作為失敗OAuth的因應措施 |
| 外掛程式會連線，但無法叫用動作 | 確認外掛程式已附加至聊天、動作已公開至模型，且已部署最新版本 |
| 外掛程式使用錯誤的環境 | 使用預期的階段或生產MCP伺服器URL編輯或重新建立外掛程式 |
| 外掛程式仍會顯示舊版動作中繼資料 | 部署變更，選取ChatGPT連線上的&#x200B;**重新整理**，然後開始新的交談 |

如果問題持續發生，在聯絡Beta團隊之前，先記錄應用程式名稱、環境、失敗的步驟、時間以及顯示的錯誤訊息。 請勿包含機密或敏感的客戶資料。
