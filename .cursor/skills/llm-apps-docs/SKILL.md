# LLM應用程式檔案

為Adobe LLM應用程式建立工作導向、可驗證的公開檔案。

## Source-of-truth順序

依下列順序驗證產品宣告：

1. 目前在`https://experience.adobe.com/#/@llmapps/llm-apps/`的生產UI
2. 工作區中目前可用的UI和API實作
3. 目前的公用SDK和範本行為
4. 現有的公開檔案

如果「生產」與來源或計畫衝突，請記錄「生產」並報告不相符。 請勿發佈目前可用的近期工作流程。

## 開始每項任務

1. 讀取`help/main-toc/TOC.md`。
2. 閱讀目標文章和直接相關的文章。
3. 使用[content-model.md](content-model.md)將內容分類。
4. 識別需要驗證的UI標籤、URL、命令和合約。
5. 讓各頁面的端對端範例和術語保持一致。

## 製作規則

- 透過自動建立應用程式為初次使用者創造機會（**[!UICONTROL 自動建置我的應用程式]**&#x200B;流程）。
- 組織使用者歷程和結果的導覽，而非實施主題。
- 在每個指南開頭附近說明歷程順序，並提供下一個共用步驟。
- 請勿在面向客戶的檔案中使用內部代碼名稱（例如「入門代理程式」），產品UI中永遠不會顯示這項功能。 一般地描述它（例如「平台」），並使用確切的UI副本，例如&#x200B;**[!UICONTROL 自動建置我的應用程式]**&#x200B;作為控制項。
- [!DNL Adobe LLM Apps]與平台無關 — 其MCP伺服器可搭配任何支援的LLM平台使用，而不僅僅是[!DNL ChatGPT]。 請勿將一般或說明性宣告當成唯一目標（例如，偏好使用「支援的LLM平台，例如[!DNL ChatGPT]」，而非「ChatGPT」）。 [!DNL ChatGPT]在真正且目前特定於[!DNL ChatGPT]的內容中僅明確命名[!DNL ChatGPT]：ChatGPT指南中的專用[測試](/help/guides/test-in-chatgpt.md)、其直接交叉連結/程式步驟，以及[!DNL ChatGPT]特定參考或疑難排解內容。
- 在使用者第一次遇到技術概念時加以說明；連結至更深入的概念或參考資料。
- 讓教學課程保持線性、以作業為中心的操作指南和參考頁面符合實際。
- 僅包含讀者目前工作所需的資訊；偏好短而直接的句子。
- 在整個歷程中使用一個代表性應用程式。
- 區分產生的支架和生產就緒的整合。
- 避免內部工作者名稱、資料庫欄位、實作票證和不穩定的管道詳細資訊。
- 請勿在參考線間複製欄位表格；參考連結。
- 保留Experience League前端內容和指示詞： `[!DNL]`、``、`[!IMPORTANT]`、`[!NOTE]`和`[!TIP]`。
- 使用根目錄相對內部連結： `/help/...`。
- 標題和標題使用句子大小寫，除非產品標籤另有要求。
- 使用說明性影像替代文字，說明畫面和狀態。

## 受保護的PM認可敘事

在`help/overview/overview.md`中，這些區段已由PM核准：

- **您可以使用LLM應用程式做什麼**
- **為什麼LLM應用程式很重要**

保留其標題、專案符號、用語、順序和索賠逐字記錄。
請勿在一般檔案編寫期間加以縮短、重寫、重新整理或移除
更新。只有在使用者明確要求變更任一區段時，才能變更該區段，並且
確認新復本已由PM核准。

## 安全性需求

- 絕對不要包含認證、權杖、私人URL、個人資料、內部主機名稱或客戶識別碼。
- 顯示從Managed設定載入的秘密，從未硬式編碼。
- 外部服務需要HTTPS。
- 驗證外部輸入和上游回應。
- 使用安全的DOM API轉譯外部值；不建議將其內插到`innerHTML`。
- 建議最低許可權的GitHub應用程式、API、CSP、CORS和瀏覽器許可權。
- 使用安全且面向使用者的錯誤，並避免記錄敏感性資料。

## 熒幕擷圖工作流程

如需新的或重新整理的影像，請遵循[screenshots.md](screenshots.md)和[screenshot-manifest.md](screenshot-manifest.md)。

預設工作流程會使用使用者建立的生產擷取套件：

1. 尋找`docs-captures/<run-id>/`下的熒幕擷取畫面，或使用使用者提供的資料夾。
2. 清查並視覺化檢查每個PNG、JPEG和WebP檔案；請勿僅依賴其檔案名稱。
3. 使用可見的UI內容比對熒幕擷取畫面與資訊清單狀態。
4. 在變更檔案之前，報告遺失、重複、模稜兩可、過時或不安全的擷取。
5. 保留來源擷取不變。
6. 使用`help/assets/`下的穩定資訊清單檔案名稱，建立經過清理的最終副本。
7. 更新教學課程和相關指南，以符合實際擷取的生產工作流程。
8. 新增準確的替代文字並執行檔案驗證。

代理程式引導的瀏覽器擷取仍為選擇性遞補。 請勿儲存瀏覽器狀態或認證，也不要在CI中執行生產變異熒幕擷取畫面。

系統要求「從熒幕擷取畫面更新檔案」時：

- 將最新明確選取的擷取資料夾視為來源。
- 只有在應用程式流程或熒幕擷取畫面對應完全模稜兩可時才會詢問。
- 絕不認可原始擷取資料夾。
- 未經明確核准，請勿刪除或修改來源擷取。
- 如果在不模糊任務的情況下無法移除敏感資訊，請要求安全的重新擷取。

## 建立稽核封存

產生可共用的離線HTML網站和ZIP封存：

```bash
node .cursor/skills/llm-apps-docs/scripts/build_review_bundle.mjs
```

組建會寫在存放庫旁邊，而不是在存放庫內部。 僅包含
已發佈的文章和已清理的資產，轉換Experience League指示
供離線檢閱，並注意其樣式並非最終體驗
聯盟轉譯。

## 驗證

執行：

```bash
python3 .cursor/skills/llm-apps-docs/scripts/validate_docs.py
```

在移交之前修復每個遺漏的內部文章、遺漏資產、無效的根相對路徑和遺漏的字首欄位。

另請檢查：

- UI標籤和熒幕擷取畫面與生產環境相符。
- 指令碼和Widget URL範例在指南和參考之間具有一致性。
- 指令與目前的樣板相符。
- 新頁面會從目錄連結。
- Adobe文章驗證工作流程會在可用時通過。
